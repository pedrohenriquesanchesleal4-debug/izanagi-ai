# References — Breaking Change Detector

> Curadoria dos melhores sites/referências (2026) para identificação, versionamento e comunicação de breaking changes. Use como fonte de padrões e inspiração.

## Docs canônicas
- [SemVer](https://semver.org/) — especificação oficial de versionamento semântico.
- [Keep a Changelog](https://keepachangelog.com/) — convenção de changelog para comunicar mudanças quebradas.
- [npm Docs](https://docs.npmjs.com/) — regras de semver, deprecated e breaking changes no registry.
- [semantic-release](https://github.com/semantic-release/semantic-release) — automação de versão e changelog a partir do commit (repo).

## Referências e inspiração
- [Node.js previous releases](https://nodejs.org/en/about/previous-releases) — cronograma de releases e deprecations do runtime.
- [Chrome Platform Status](https://chromestatus.com/) — deprecations e breaking changes de plataforma web.
- [Can I Use](https://caniuse.com/) — compatibilidade real de features e removal announcements.
- [GitHub Blog](https://github.blog/) — anúncios de breaking changes em produtos e APIs do GitHub.

## Comunidade / galerias / exemplos
- [MDN Browser Compatibility](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Page_structures/Compatibility_tables) — tabelas oficiais de compatibilidade e rupturas.
- [Semantic Roles](https://github.com/semantic-release/semantic-release/releases) — exemplos reais de versões e changelogs gerados.
